# البحث الموحد في لوحة الإدارة

المدخل: خانة البحث في أعلى اللوحة أو Ctrl/Cmd+K. اكتب حرفين على الأقل، ثم اختر نتيجة أو نوعًا محددًا. الأسهم تتنقل بين النتائج، Enter يفتح التفاصيل الحالية، وEscape يغلق النتائج. «تحميل المزيد» يتابع الصفحات دون اقتصار البحث على البيانات المحمّلة في الجدول.

## النطاق الحالي

| النوع | حقول البحث الأساسية |
|---|---|
| الأصناف المشتركة والمنتجات | الاسم، SKU، الباركود، العلامة، التصنيف، الوصف، مواصفات الصنف، متغيراته وألوانه ومقاساته |
| المتاجر | الاسم العربي والإنجليزي، النشاط، التصنيف، العنوان |
| عروض التجار | اسم التاجر ومعرفات الصنف والمتجر والمتغير |
| الطلبات | الرقم، العميل والهاتف، الوزارة والدور والغرفة، المندوب، ملخص الأصناف النصي |
| المستخدمون والفريق | الاسم، البريد، الهاتف، الجهة، الدور ومعرف المتجر |
| الشراكات والتوظيف | حقول الاسم والهاتف والبريد والمتجر والوظيفة والحالة الموجودة بالسجل |
| الخصومات | الكود والعنوان والوصف |
| سجل التدقيق | العملية والمنفّذ ونوع ومعرف السجل والحالة؛ لا تُفهرس بيانات قبل/بعد التغيير |
| أقسام الإدارة | أسماء الأقسام؛ اقتراحات محلية فورية |

يعالج اختلاف أشكال الألف والتشكيل والتطويل والأرقام العربية والإنجليزية وحالة الحروف اللاتينية. يُفهرس أول حرفين إلى 32 حرفًا من كل كلمة، مع مطابقة جميع كلمات الاستعلام. البحث ببادئات الكلمات، وليس محرك أخطاء إملائية أو بحثًا دلاليًا. لا يَعِد بقدرات أو حجم أنظمة فيسبوك. يمكن استبدال طبقة الاسترجاع لاحقًا بمحرك متخصص عند الحاجة للترتيب المتقدم والمرادفات والتصحيح الإملائي.

## طريقة التنفيذ والتحديث

- `adminSearchIndex/{sha256(source/id)}`: إسقاط بحث خاص بالإدارة، من حقول مسموحة صراحةً. مصدر الحقيقة يبقى المستند الأصلي.
- `adminSearchControl/state`: مؤشر تهيئة قابل للاستكمال. كل طلب يراجع حتى 60 مستندًا من مجموعة واحدة، دون تحميل قاعدة البيانات كاملة في عملية بحث.
- عند أول بحث يُجهّز الفهرس تلقائيًا إذا لم يكن جاهزًا. إذا تجاوزت آخر مراجعة خمس دقائق، تبدأ مراجعة عند البحث التالي. بعد اكتمالها تُعاد نتيجة الاستعلام تلقائيًا.
- زر «تحديث الفهرس» يبدأ مراجعة جديدة أو يستكمل مراجعة غير مكتملة. تُراجع المجموعات بالترتيب. عند إغلاق اللوحة تتوقف متابعة الدفعات؛ تُستكمل لاحقًا من المؤشر المحفوظ.
- تعديلات الكتالوج والاستيراد والطلبات التي تمر عبر `auditInTransaction` تُحدّث الإسقاط في المعاملة نفسها. واجهة إدارة المستخدمين تحدّث إسقاط الحساب والفريق داخل معاملة إكمال التغيير.
- تسجيلات الموبايل وكتابات العميل/وحدة التحكم المباشرة لا تمر جميعها بالخادم؛ تدخل في البحث في المراجعة التالية. هذه **مزامنة دورية عند الاستخدام وليست Trigger لحظيًا عامًا**. للتحديث الفوري على كل كتابة خارج واجهات الخادم، يلزم نشر مشغّل تغييرات مستقل لاحقًا.
- تُقرأ المستندات الأصلية للنتائج قبل إرجاعها. المستند المحذوف أو الذي لم يعد يطابق البحث لا يظهر رغم وجود إسقاط قديم. لا تحذف المراجعة الإسقاطات اليتيمة ماديًا؛ يلزم تنظيف دوري عند توسع البيانات.
- لا تُكرر المنتجات المسقطة من عروض التجار كأصناف بحث مستقلة. تظهر هويتها المشتركة وعروض التجار كلٌ بنوعه.
- صفحة النتائج تقرأ حتى 61 مرشحًا وتُرجع 60 منها كحد أقصى قبل التصفية. عدد النتائج المعروض ليس عدًّا كليًا لكل السجلات؛ تابع الصفحات حتى انتهاء المؤشر.
- عرض تفاصيل النتيجة يستخدم حقولًا مسموحة، مع زر فتح القسم المختص. المستخدم يُبحث بمعرّفه، والصنف المشترك يُجلب بمعرّفه حتى لو لم يكن ضمن أول 50 صنفًا، وسجل التدقيق يُفتح مباشرة. بقية الأقسام تعيد استخدام أدوات التصفية الحالية.

## الفهارس والنشر

البحث العام يستخدم فهرس مصفوفة أحادي الحقل على `prefixes` الموجود افتراضيًا. أُضيف فهرس مركب `prefixes ARRAY_CONTAINS + source ASC` لتسريع تصفية النوع. حتى نشره/اكتمال بنائه، يعمل البحث بفهرسه العام مع تصفية النوع على دفعات؛ قد يحتاج «تحميل المزيد» للعثور على النوع المختار.

من نسخة المستودع المحدثة، بحساب Firebase مالك المشروع أو ذي صلاحية إدارة الفهارس:

```sh
npx --yes --package firebase-tools firebase deploy --only firestore:indexes --project capital-talabat
```

هذا الأمر ينشر تعريف الفهرس، ولا يستورد بيانات تجريبية. تهيئة محتوى فهرس البحث تتم من اللوحة. لم يُنشر الفهرس المركب إلى المشروع الحي أثناء التطوير، ولم تُكتب بيانات تشغيل حية للاختبار.

استُثنيت `text/title/detail/indexedAt` في مجموعة البحث من الفهارس غير المستخدمة لتقليل الكتابات وحجم الفهارس. لا نُفهرس كل حقل تلقائيًا؛ يُضاف الفهرس للاستعلام الذي يحتاجه فعلًا.

## الصلاحيات والخصوصية

كل طلب بحث وقراءة تفاصيل وتحديث فهرس يمر بتحقق الإدارة الخادمي الحالي، بما فيه تعطيل الحساب وإلغاء الجلسة. لا تسمح القواعد الحالية بقراءة أو كتابة مجموعتي الفهرس والتحكم لأي عميل، حتى عميل الإدارة؛ الوصول عبر الخادم فقط.

لا تُفهرس كلمات المرور، مفاتيح الوصول، OTP، بيانات الدفع، رصيد المحفظة، تكاليف الشراء، الربح، أو محتوى سجل التدقيق التفصيلي. لا تحفظ استعلامات البحث في السجل ولا في LocalStorage. نتائج الحسابات تعرض بيانات اتصال داخل لوحة الإدارة فقط.

تهيئة الفهرس تضيف قراءات وكتابات بحسب عدد السجلات؛ ليست عملية مجانية عند كبر البيانات. مرحلة الإنتاج الأكبر تحتاج تحديثًا بالأحداث وتنظيف الإسقاطات وسياسة احتفاظ بالسجلات بدل مراجعة تاريخ غير محدود كل مرة.

## التحقق

- `npm run test:admin-search`: تطبيع العربية، أكواد وباركود وأرقام، حجب الحقول الخاصة وحدود حجم الإسقاط.
- `npm run test:search-emulator` يشغّل اختبارات التكامل والأمان على المحاكي المحلي فقط.
- `tests/admin-search.integration.test.ts`: محاكي محلي، 135 منتجًا يتجاوز حدود الصفحة، مستخدم غير محمّل، تحديثات المعاملات، حذف وتعديل السجلات، وإعادة المراجعة لتسجيل موبايل جديد.
- `tests/firestore.security.test.ts`: منع وصول العملاء إلى الفهرس وحالته.
- `npm run test:admin-layout`: اقتراحات خادمية غير محمّلة محليًا، تجاهل الرد القديم، الصفحات، تفاصيل النتيجة، فتح المستخدم، الكيبورد، ومقاسات 320/390.
