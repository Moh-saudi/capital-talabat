# معاينة خدمة طلبات العاصمة

هذا فرع معاينة للموقع العام، لا يغيّر عقد الموبايل أو مجموعات Firebase أو قواعدها أو المصادقة أو مستخدميها. لا يوجد نشر Firebase ضمن هذه المهمة. لا يُدمج في main قبل مراجعة المعاينة.

## مصادر الإعدادات

- `src/config/ministries.js`: الجهات الـ42، بالنصوص المعتمدة.
- `src/config/site.js`: الوزارة المخدومة، المواعيد، الحد الأدنى، رسوم التوصيل، شرائح الجملة، واتساب، الإيميل ورابط التطبيق.
- `src/config/menu.js`: المنيو وأسعاره وتوافره وصوره. الأسعار null تمنع الإضافة، بما فيها أسعار أحجام الكشري. لتسعير صنف ذي أحجام، املأ سعر كل حجم تريد إتاحته.
- `.env.example`: `VITE_SIGNUP_URL` بعنوان Google Apps Script العام الافتراضي، و`VITE_MOBILE_APP_URL` لرابط التطبيق الرسمي. `APP_URL` داخل site.js هو رابط التطبيق فقط؛ متغير الخادم القديم `APP_URL` لم تتغير دلالته أو قيمته.

المنيو والسلة الجديدة مستقلان عن Firebase، والسلة في state فقط وتُمسح عند إعادة التحميل. لا تُحفظ الطلبات الجديدة في لوحة الإدارة: إرسال واتساب يفتح رسالة للتنسيق، ولا يعني دفعًا أو قبولًا تلقائيًا. عند عدم تحديد الرسوم أو الحد الأدنى تظهر ضرورة تأكيدهما قبل الدفع، ولا تُعامل الرسوم المجهولة على أنها صفر.

## التسجيل في Google Sheets

`src/lib/submitSignup.ts` هي نقطة الإرسال الوحيدة. ترسل POST بنوع `text/plain;charset=utf-8` وبالحقول `name, phone, ministry, bus_line, website` فقط. الرقم يُوحّد إلى E.164 مثل `+201012345678`. الحالات supported: served / waitlist / duplicate / ignored. لا تستخدم no-cors ولا تفترض النجاح عند تعذر قراءة الرد.

اختُبرت الحالات بأجوبة محاكية، دون إرسال بيانات اختبار إلى الشيت الحقيقي. يلزم إجراء تسجيل حقيقي مصرح به من صاحب المشروع في المعاينة للتأكد من صلاحية نشر Apps Script للعامة وقراءة الرد من المتصفح. إذا منعت الخدمة الرد، يعرض الموقع إعادة المحاولة وواتساب بدل نجاح وهمي. التحقق المحلي والحقل المخفي لا يحلان محل تحقق وحماية Apps Script نفسه.

## الصفحات والآليات المحفوظة

- `/careers`: نفس العرض وروابط استفسارات واتساب حسب الفريق؛ توحيد الرقم من config فقط.
- «انضم كشريك»: نفس رسالة واتساب وآلية الفتح الحالية؛ لا نموذج جديد ولا كتابة إلى collection.
- `/admin` و`/kitchen`: نفس التطبيق المحمي والمصادقة والصلاحيات. الرابط مخفي من الفوتر، وترويسة X-Robots-Tag تمنع الفهرسة، ولا تمنح أو تلغي أي صلاحية.
- `/privacy` و`/terms`: مسودتان معلنتان للمراجعة القانونية. مدة الاحتفاظ 180 يومًا مقترحة من config وليست وظيفة حذف آلية من الشيت.

أُزيلت اللقطات المستخرجة من فيديو الطرف الثالث ورابط المصدر. الصور الحالية للمنيو والشنطة placeholders، ورسم الهيرو توضيحي بالهوية، ولا يدّعي تصوير منتج أو تغليف فعلي. الصور النشطة WebP، وأيقونات PNG بمقاساتها الصحيحة. بيانات المشاركة تتضمن صورة PNG 1200×630 بمسار absolute وOrganization/LocalBusiness دون تقييمات أو عناوين أو أسعار مختلقة.

## الاختبارات المنفذة

- `npm run lint`
- `npm run test:public-service`: تحقق الأسعار، الوزارة، الموبايل، مواعيد القاهرة، رسالة الطلب وردود التسجيل المحاكية.
- `CHROMIUM_PATH=/usr/bin/chromium npm run test:public-web`: مقاسات 320/360/390/768/1440، المنيو والسلة، الحد الأدنى ورسوم التوصيل بأسعار اختبار محلية معترضة في المتصفح فقط، منع الجهة غير المخدومة، حالات التسجيل والخطأ وإعادة المحاولة، الجملة والسياسات والوظائف.
- `VERCEL_ENV=preview npm run build`
- `CHROMIUM_PATH=/usr/bin/chromium node tests/pwa-build.browser.mjs`: تحديث صفحات الإنتاج، العمل دون إنترنت، المقاسات وتقليل الحركة، دون إنشاء حسابات.

لم تُشغّل أوامر Firebase أو اختبارات المحاكيات التي تنشئ مستخدمين. Workflow المعاينة الجديدة يشغّل اختبارات الموقع العام فقط. لا حاجة لأي مفاتيح Firebase جديدة لتجربة المنيو أو التسجيل.

## مطلوب يدويًا قبل إطلاق البيع

1. املأ أسعار menu.js وأسعار الأحجام، ثم راجع التوافر. لا يستطيع الزائر إضافة الأصناف غير المسعّرة.
2. حدد MIN_ORDER وDELIVERY_FEE بالجنيه، ونسب BULK_TIERS إذا اعتمدتم خصومات فعلية؛ لا توجد نسب مفترضة.
3. اجعل تبويب Served في Google Sheets مطابقًا تمامًا لـSERVED_MINISTRIES، مبدئيًا «وزارة الصحة والسكان». لا يكتب الموقع هذه القائمة إلى الشيت تلقائيًا.
4. اختبر تسجيلًا حقيقيًا واحدًا بموافقة صاحبه، وتأكد من وصول الرد، ومن توحيد صيغة الرقم والتعامل مع التكرار في Apps Script.
5. أضف الصور المملوكة للمنتجات والشنطة الفعلية، ثم حدّث image في المنيو وصورة قسم الشنطة. راجع أن التغليف الفعلي يطابق وصف الختم والاسم ورقم الطلب.
6. ضع CONTACT_EMAIL المعتمد. يبقى رابط الإيميل مخفيًا حتى إضافته.
7. راجع مسودتي الخصوصية والشروط قانونيًا، واعتمد سياسة الإلغاء والاسترداد ومدة الاحتفاظ وطريقة تنفيذ طلبات الحذف.
8. أكد حسابات InstaPay وفودافون كاش مع فريق التشغيل. لا توجد أرقام دفع مخترعة أو تحقق دفع آلي.
9. أضف VITE_MOBILE_APP_URL عند نشر التطبيق رسميًا. حتى ذلك الحين يظهر «التطبيق قريبًا»، ويظل الطلب عبر واتساب.
10. راجع Vercel Preview واعتمد الانتقال إلى main في خطوة منفصلة.

## اقتراح فقط: SSG

المشروع Vite SPA. يمكن لاحقًا توليد HTML ثابت للصفحات العامة (`/`, `/careers`, `/privacy`, `/terms`) لتحسين فهرسة محتواها، مع إبقاء لوحة الإدارة ديناميكية. لم يُضف SSR/SSG أو إطار جديد في هذه المعاينة.
